# Glossary — AI-Enabled Coding Interviews

Ubiquitous language for this repository. Implementation details are out of scope.

## Terms

- **AI Trap** — A plausible-but-wrong solution an LLM produces for a case; the case is designed so a blind copy-paste fails on it.
- **Vibe-Coder** — A candidate who accepts AI output without review; scores 1–2 on the 7 criteria.
- **Divide and Conquer** — The 5-step workflow: Understand → Plan → Prompt → Review → Test.
- **Checkpoint** — One of the 4 task stages in a case (Explore, Fix, Implement, Edge cases & defense).
- **Seeded defect** — A bug deliberately injected into the clean-room workspace before the session.
- **Clean-room workspace** — A clone of the source repo with `.git` stripped so history cannot be inspected.
- **AI-Slop rescue** — A case where the starting code is a plausible but flawed AI-generated PR the candidate must audit and repair.
- **Hard taxonomy pillar** — One of five difficulty mechanisms: deceptive abstractions, toy-vs-production scale, conflicting invariants, concurrency/idempotency, AI-slop rescue.
- **Criterion (1–7)** — One of the seven evaluation competencies; scored 1–4.
- **Level calibration** — Mapping L3–L6+ to Easy/Medium/Hard tiers.
- **Polyglot case** — A case supporting multiple languages (Python, TS, Go, Java, Rust, C#).
- **External-repo reference** — A case that links to a public GitHub repo instead of vendoring code.
